# Architecture

Spore is four Quickshell programs that don't share memory:

| Process | Folder | When it runs |
|---|---|---|
| The shell | `shell/` | the whole session (`spore`, from `spawn-at-startup`) |
| Files | `shell/files.qml`, `shell/files/` | while one of its windows is open (`spore-files`) |
| The video players | `video/` | only while a video wallpaper plays (`shell.qml`) or the quick view plays a file (`preview.qml`); they exit when done |
| The greeter | `greeter/` | before login, inside `cage` (`spore-greeter`) |

They talk through files: the shell writes its state to
`~/.local/state/spore/` (Files follows the theme from there) and a copy to
`/var/lib/spore/<user>/` for the greeter; the player reports through its
standard output.

## The shell (`shell/`)

`shell.qml` is the entry point and the **owner of the state**: the wallpaper,
the palette, the mode, which window is open and on which page. It creates a
single instance of each service and passes it as a property to whoever uses
it (`required property Theme theme`, `property Weather weather`…). The other
files don't keep global state: they receive what they need and report with
signals (`wallpaperChosen`, `controlCenterRequested`…), and `shell.qml`
decides.

### Folders

**`common/`**: what everything else uses.

| File | What it is |
|---|---|
| `Theme.qml` | the palettes (Spore, Catppuccin, Ayu, Wallpaper) and every derived color; no other file has loose colors |
| `Icon.qml`, `lucide.js` | Lucide icons (and Simple Icons logos); `lucide.js` is generated by `tools/lucide.mjs` |
| `SporeMark.qml`, `brand.js` | the logo and the brand's texts and colors |
| `UiText.qml`, `MonoText.qml` | interface text (Noto Sans) and numbers (JetBrains Mono), always as plain text |
| `session.js` | starting apps (the launcher, a drive's folder, a file's app, a terminal) with the session's environment, which the wrappers in `nix/bin` keep before adding Spore's PATH and Qt variables |
| `CcButton`, `CcCard`, `CcSwitch`, `CcSlider`, `CcSegmented`, `CcSection`, `CcProgress`, `CcGraph` | the design's controls (they were born in the Control Center, hence the `Cc`; About, power and notifications use them too) |

**`services/`**: data and state, no interface.

| File | What it is |
|---|---|
| `Settings.qml` | reads and saves `~/.config/spore/settings.json` |
| `Compositor.qml`, `NiriCompositor.qml` | the compositor in a neutral shape (workspaces, windows, screens, radius, focus, turn off monitors, quit) and its niri implementation (event-driven, no polling). See below |
| `NotificationService.qml` | the notification server: history, unread, Do Not Disturb |
| `SystemMonitor.qml` | CPU, memory, GPU, network and disks, measured once for everyone |
| `SystemInfo.qml`, `UserInfo.qml` | machine data (About) and user data (Home), read at startup |
| `Weather.qml`, `Geocoder.qml`, `Sun.qml` | weather (Open-Meteo), place lookup, sunrise and sunset |
| `WallpaperService.qml` | the wallpaper list, their thumbnails and the videos' frames |
| `ClipboardService.qml` | the clipboard history (cliphist) |
| `BluetoothAgent.qml` | pairing with an agent: while a pairing runs, `bluetoothctl` is BlueZ's default agent, and the code to type on a keyboard (or to compare with a phone) shows on the Bluetooth page; the device is trusted once paired |
| `BrightnessService.qml` | the screens' brightness: external monitors over DDC/CI (ddcutil) and a laptop's backlight, read when the Control Center opens; a slider sends only its latest value |
| `DrivesService.qml` | external drives (udisks): mount, unmount, eject; and, for Files, the internal disks' volumes worth opening (with their `/etc/fstab` folder) |
| `SystemTheme.qml` | carries the palette and mode to GTK, kitty, rofi, Zed… ([appearance](appearance.md)) |
| `Idle.qml` | lock, turn off monitors and suspend on idle, and lock before any sleep |

**`bar/`**: the bar (`Bar.qml`, one per monitor) and its pieces
(`Capsule`, `BarButton`, `BarText`, `BarTooltip`). Each widget is a file
(`Audio`, `Clock`, `Workspaces`, `SystemButton`, `DrivesButton`…); `Bar.qml`
lays them out from `bar.layout` in `settings.json`.

**`controlcenter/`**: `ControlCenter.qml` (the panel: tabs at the top and the
chosen page) and one page per file: `CcHome`, `CcMedia`, `CcAudio`,
`CcSystem`, `CcNetwork`, `CcBluetooth`, `CcDrives`, `CcWeather`,
`CcCalendar`, `CcNotifications`. Each page is created when shown (so the
wifi only scans for networks with Network open).

**`panels/`**: the other windows: `SettingsWindow`, `AboutPanel`,
`ClipboardPanel`, `PowerMenu`, `NotificationPopups`, `NotificationCard` and
`FilePicker` (the file and folder picker: a layer above everything, not a
window niri would put in the tiling; anyone requests it from `shell.qml`
with `openPicker({ purpose, mode, title, folder, filters })`).

**`lock/`**: the lockscreen ([details](lockscreen.md)).

**`wallpaper/`**: `Wallpaper.qml` (the background, one per monitor, with the
transitions from `shaders/`), `VideoPlayer.qml` (starts the `video/`
process), `WallpaperStrip.qml` (the "Preview on desktop" strip) and
`WallpaperThumb.qml`.

### The compositor

`services/Compositor.qml` is the only thing that knows which compositor is
running: it detects it from the environment (`NIRI_SOCKET`,
`HYPRLAND_INSTANCE_SIGNATURE`), loads its implementation and always exposes
the same shape: `workspaces` (`{ id, index, name, output, focused, active,
occupied }`), `windows` (`{ id, appId, title, workspaceId, focused, urgent,
lastFocused }`), `focusedWindow`, `outputs`, `cornerRadius`, `name`,
`version` and the actions (`focusWorkspace(ws)`, `focusWindow(w)`,
`powerOffMonitors()`, `quit()`, `emptyWorkspace()`). The rest of the shell
only uses that. The full shape is documented in the file itself.

Today there's one implementation, `NiriCompositor.qml`: it reads
`niri msg event-stream` (a single process, no polling) and translates niri's
data into that shape. Adding another compositor means writing another one,
for example `HyprlandCompositor.qml` with the `Quickshell.Hyprland` module,
and loading it in `Compositor.qml`.

Two niri things live outside the shell: `SystemTheme.qml` writes the border
colors to `niri.kdl` (as it does for kitty or GTK), and the greeter launches
the session the user picks.

### Imports

Within a folder, files see each other; to use another folder's you import it,
and each file imports only the ones it uses:

```qml
import "../common"      // Theme, Icon, UiText…
import "../services"    // Weather, NotificationService…
```

Quickshell doesn't allow importing anything **outside** the entry point's
folder (`shell/`): that's why the greeter can't use `shell/common/Theme.qml`,
and its package copies one into it at build time (`nix/greeter.nix`).

### File paths

For an image or a program you have to build the real path:
`Quickshell.shellPath("../assets/…")` or `Quickshell.shellDir`. A relative
`source` in an `Image` resolves against Quickshell's own resource system, not
against the disk. What sits next to the file (the shaders) does work with
`Qt.resolvedUrl("shaders/…")`.

### Windows that exist only while open

The Control Center, Settings, About, the clipboard and the power menu are
loaded with a `LazyLoader` that depends on a `shell.qml` state
(`controlCenterOpen`, `ui`…). That's why their `IpcHandler`s live in
`shell.qml`: they have to exist even when the window doesn't.

### Why there's no `Singleton`

The first version used a `Singleton` for the wallpaper and it failed in two
ways, confirmed live: an `IpcHandler` inside it never registered, and its
`Component.onCompleted` never ran (the path stayed empty, with no warning).
Since then, shared state is created in `shell.qml` and passed as a property.

### How an image finds out it changed

The wallpaper is always copied to the same file
(`~/.local/state/spore/wallpaper.jpg`), so `shell.qml` also keeps a version
number and every `Image` uses `path + "?" + version`: when the URL changes,
Qt reads the file again.

## The video player (`video/`)

QtMultimedia holds on to hundreds of MB of decoder memory even after the
`Video` is unloaded, so the shell doesn't load it: `wallpaper/VideoPlayer.qml`
starts `video/shell.qml` as another Quickshell, which opens a surface per
monitor right above the background (the `Bottom` layer), plays the video
once, reports `SPORE_VIDEO:showing` and exits. When it exits, the memory goes
back to the system. Details in [appearance](appearance.md#video-wallpapers).
`preview.qml`, in the same folder, is the one for Files' quick view (see
below).

## Files (`shell/files.qml`)

The file manager ([what it does](files.md)) is another process:
`spore-files` starts `quickshell -p shell/files.qml`, or, if Files is
already running, asks it for another window over IPC. It lives in `shell/`
and not in a folder of its own because Quickshell doesn't import from
outside the entry point's folder, and it uses the shell's `Theme` and
controls. Its windows are regular windows (`FloatingWindow`, app id
`spore-files`) and the process exits when the last one closes.

- `files.qml`: the windows, what they share (view, order, hidden files,
  remembered in `files.json`) and the `files` IPC. The theme comes from
  `theme.json`, which the shell writes with the mode already resolved (Files
  can't resolve "auto" by itself), and `colors.json`; the fonts, from
  `settings.json`.
- `FilesWindow.qml`: navigation (every path is checked with a small `sh`
  before going in: it exists, it can be read, the free space), the history,
  the selection and the keys. The selection is kept by name, not by row, so
  it stays on the same file when others appear, the order changes or a
  filter applies.
- `FolderModel.qml`: `FolderListModel` reads the folder and follows it, and
  a `SortFilterProxyModel` sorts it (folders first, numbers as numbers).
  The folder goes in through `folderUri` (`fileutil.js`): Qt 6.11's model
  reads its path as a URL a second time, so a "#", "?" or "%41" in it listed
  another folder ("C# stuff" showed "C"). The file picker uses it too.
  Filtering doesn't go in the proxy: Qt 6.11's `FunctionFilter` crashed the
  process every time it ended or reloaded (it destroys an object it created
  in a context that's already gone), so while filtering the views show a
  list of the matches, remade when the folder changes.
- `Thumbnails.qml`: the freedesktop cache (`~/.cache/thumbnails`), which
  names each thumbnail after the MD5 of the file's URI written the way GLib
  writes it (`fileutil.js`). A single process per folder checks which exist,
  reading the files on its stdin (as arguments, tens of thousands of files
  went over the system's limit).
- `Bookmarks.qml`: the favorites, GTK's bookmarks file (the one Thunar and
  the GTK dialogs use), read again when another app changes it and written
  all at once, keeping the lines that aren't local folders. One for every
  window.
- `Recents.qml`: the Recent place, from the freedesktop history
  (`recently-used.xbel`), read once a window shows it and again whenever
  another app rewrites it; one `stat` says which files are still there
  (and again after each operation). `FolderModel` shows it as a list of its
  own, newest first, where an entry's path comes from the list (two files
  can share a name, so the views get "name (folder)"); the window takes
  `recent:///` as its folder and doesn't paste, make or drop anything there.
  What Files opens is added the way GLib does it (Files among the apps that
  used it, read right before writing and written to a new file renamed over
  it). A second bookmark for one file would make GLib refuse the whole list
  (and GTK apps start a new one over it), so a list that doesn't look as
  GLib writes it is left alone.
- `FileOps.qml`: copy, cut and paste (and drops, with `transfer`), rename,
  new folder and the Trash (sending, and in the home Trash restoring,
  deleting for good and emptying, by the freedesktop spec, without needing
  gvfs), compressing and extracting (bsdtar, with what it has read for the
  progress), one for every window (a shared clipboard), one job at a time.
  The work is done by coreutils, gio and bsdtar in small scripts that get
  the paths as arguments. Copy and cut also share to the system's
  clipboard (wl-copy: one image as PNG, converted by ffmpeg if needed;
  anything else as a text/uri-list). Nothing is overwritten (keep both,
  skip, or Replace, which sends the old one to the Trash first), a copy is
  written under a hidden temporary name and renamed when complete, and
  deleting is `gio trash`.
  Files doesn't end while a job runs, even with no windows left.
- `QuickView.qml`: the quick view (Space), a layer-shell panel that never
  takes the keyboard (the arrows stay in the window, and the view follows
  the selection). The card changes once the next file is ready (read;
  decoded, with `Image.retainWhileLoading` keeping the last one meanwhile),
  in one step; if that takes more than 300 ms, the next one's info card
  shows meanwhile. A PDF's page is drawn by pdftoppm just as big as
  it shows, in the screen's pixels (pdfinfo gives the page's shape and how
  many there are), into a PPM in `$XDG_RUNTIME_DIR`: uncompressed, as a
  PNG's compression takes several times longer than drawing the page. The
  file is removed once decoded; one left behind (Files ended while a page
  was drawn) is swept a minute later. An archive's contents come from
  `bsdtar -tv` (awk keeps the first 1000 entries and counts them all) and
  become a tree in QML. bsdtar runs under `setpriv --pdeathsig`, so the
  script ending (the view moving on) stops a long read. Videos and songs play in `video/preview.qml`, a process
  of its own drawn right over the panel's empty area (niri puts the newest
  surface on top): QtMultimedia keeps the decoder's memory until its process
  ends (measured: 43 MB before a 4K video, 376 MB after unloading it), so it
  ends as soon as the view moves on. `setpriv --pdeathsig` ends it if Files
  goes away without closing it.
- `FileGrid.qml`, `FileList.qml` (an entry's clicks and drags:
  `EntryArea.qml`; folders, places and the path's pieces take drops through
  `DropTarget.qml`, and the window draws what's dragged and drops it),
  `FileIcon.qml`, `Sidebar.qml` (with the shell's `DrivesService` for the
  USB drives), `PathBar.qml`, `RenameField.qml`, `ContextMenu.qml`,
  `AskDialog.qml`, `OpenWithDialog.qml` (the apps from `gio mime`, with the
  names and icons of Quickshell's `DesktopEntries`): the views and the
  pieces.

Files open with `gio open`, the app the system has for each kind of file,
without the variables Quickshell needs (no title bar, the app id).

## The greeter (`greeter/`)

Another Quickshell, which runs as the `greeter` user before login and reads
the theme published by the last user's shell. See [greeter](greeter.md).

## Nix (`nix/`)

- `package.nix`: `spore-shell`, the shell and Files. It copies `shell/`,
  `video/` and `assets/` to `share/spore` and builds the `bin/` commands
  with their dependencies in `PATH` (cliphist, ffmpeg, matugen, curl…).
- `greeter.nix`: `spore-greeter`, the greeter on its own: `greeter/`, a
  copy of `shell/common/Theme.qml` and the default wallpaper, and
  `bin/spore-greeter` with cage.
- `bin/spore`: picks the folder (the package or `devPath`), adds QtMultimedia
  for the video process and the image plugins (WebP, TIFF, HEIC, AVIF, JPEG
  XL: qtimageformats and kimageformats) and starts Quickshell.
  `bin/spore-files` adds the same.
- `bin/spore-files` and `spore-files.desktop`: Files, and its entry in the
  app launchers.
- `home-manager.nix`: `programs.spore` (`spore-shell`, `settings.json`,
  dev mode).
- `nixos.nix`: `services.spore` (the `/var/lib/spore` folders and
  `spore-greeter` in greetd).
